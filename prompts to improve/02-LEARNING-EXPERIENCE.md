# Implementation prompt: turn evidence into effective revision

Apply this only after the reliability baseline is verified. Preserve the existing design and add the following as measured, accessible features in small tested releases. Do not implement this file merely because it exists.

1. Build a prerequisite map from the reviewed curriculum. Let students open a concept, see the few foundations it needs, attempt a brief check and follow a focused repair path back to the original question. Keep graph links evidence-backed; do not let an LLM invent prerequisites or diagnose ability from a blank response.
2. Turn post-exam findings into a revision plan. Distinguish recurring evidence from isolated slips and uncertain interpretations. For each supported gap, show the answer excerpt, relevant criterion, concept explanation, worked example, a comprehension check and a fresh transfer task from a validated family. Explain what evidence would support improvement.
3. Add spaced retrieval and interleaving using transparent scheduling rules and student control. Track delayed retention and transfer separately from immediate correctness. Let students dismiss or correct a mistaken learning-gap inference. Avoid shame-based streaks, arbitrary mastery badges or false precision.
4. Offer a dedicated English response workshop with permitted source passages, whole-response exemplars and level-grid comparisons. Offer a Maths working/notation workspace with equivalent-answer handling and step-based feedback. Add carefully reviewed science representations, data interpretation and practical planning. Keep all exam feedback until the full exam ends; lesson-practice feedback can remain a clearly separate choice.
5. Improve the reader with an accessible contents/search system, glossary, source links, useful diagrams and original print/offline study packs. Honour reduced-motion settings and keyboard navigation; the crimson path and book animation must never obscure text or trap focus.
6. Provide a trustworthy progress view: compare matched families/demand and show sample size, uncertainty, repeated attempts and changes in question difficulty. Distinguish activity, self-confidence, AI formative marks, examiner-reviewed marks and measured retention. Never manufacture cross-attempt improvement from one session.
7. Keep pseudonyms easy to use. If optional cross-device storage is proposed, explicitly distinguish it from name-only browser profiles and design real authentication before sharing private work. Provide export, correction, deletion and retention controls with clear student-facing explanations. Preserve the owner's requirement for public notes without a compulsory ChatGPT account.

For each feature deliver the concrete learner problem, evidence for the design, scope, acceptance checks, accessibility proof and observed outcome. Remove features that add visual complexity without improving learning or trust.
